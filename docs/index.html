¿Qué Hace el Proyecto a Nivel Metodológico y Científico?

El problema ontológico del formato PDF y la necesidad de una transformación con trazabilidad matemática inmutable hacia sistemas de Generación Aumentada por Recuperación (RAG).

1.1. El Problema Ontológico del Formato PDF

El formato PDF (Portable Document Format) fue diseñado en 1993 para garantizar la fidelidad de impresión visual sobre papel, no para la extracción ni la comprensión semántica de datos. En un PDF, un párrafo de texto no existe como entidad lingüística: es una secuencia de instrucciones de dibujo vectorial (operadores tipográficos con coordenadas x, y) dispersas en el flujo de la página.

Cuando los frameworks convencionales de IA y RAG (como LangChain, LlamaIndex o extractores basados en expresiones regulares simples) intentan convertir PDFs a texto plano para alimentar modelos de lenguaje grande (LLMs), incurren en cuatro patologías metodológicas críticas:

1. Pérdida Silenciosa de Contenido

Al aplicar filtros arbitrarios de longitud mínima (ej. descartar bloques menores a 60 palabras), se eliminan silenciosamente notas metodológicas cruciales, advertencias estadísticas, fórmulas y párrafos conclusivos breves.

2. Contaminación de Citas y Paginación

La técnica de solapamiento entre fragmentos (overlap) comúnmente hereda la etiqueta de la página siguiente, provocando que el LLM cite páginas físicas incorrectas al responder a los usuarios o revisores pares.

3. Alucinación de Tablas por Prosa Maquetada

Las herramientas de detección de tablas confunden párrafos justificados en dos o tres columnas con cuadrículas tabulares, fragmentando el texto en celdas rotas como "ap | plies to person | s concerned".

4. Destrucción de la Jerarquía por Cabeceras

Las cabeceras y pies de página corridos (ej. "Informe de Desarrollo Humano - Pág. 12") son interpretados erróneamente como nuevos encabezados o se incorporan al texto de los fragmentos como ruido continuo.

1.2. Los Cuatro Pilares del CIOdD-UCR PDF Intelligence Pipeline

Para resolver de raíz estas patologías, el Centro de Investigación Observatorio del Desarrollo (CIOdD) de la Universidad de Costa Rica estructuró la versión 5.2 sobre cuatro garantías matemáticas y epistemológicas:

  • Cero Pérdida de Texto Auditada (chunk_coverage ≥ 0.995): Ninguna sección corta se descarta; se absorbe controladamente en el fragmento previo registrando su procedencia.
  • Trazabilidad Bibliográfica Dual: Cada fragmento separa estrictamente el texto propio (unique_words) del solapamiento (overlap_words), registrando tanto la página PDF (índice 1-based) como la etiqueta impresa original (page_label).
  • Clasificador Heurístico Multivariable de Tablas: Evaluación de densidad, inicio en minúsculas y área para separar tablas numéricas de prosa fragmentada, aislando las rechazadas en tables_rejected.jsonl para auditoría.
  • Auditoría Criptográfica e Integridad Relacional: Huellas SHA-256 de todas las entradas y salidas registradas en manifest.json, junto con la verificación automática de 9 reglas de consistencia en integrity_report.json.

3.1. Principio Rector y Jerarquía de 5 Niveles de Evidencia

Regla fundamental: "El índice sirve exclusivamente para localizar candidatos; la evidencia debe validarse siempre contra el contenido estructurado y su trazabilidad documental primaria."

Nivel 1 — Evidencia Primaria Fáctica

Archivos: pages.parquet, tables.parquet.

La representación más fidedigna del documento original. Obligatoria para verificar cifras cuantitativas, fórmulas, citas textuales y tablas complejas.

Nivel 2 — Evidencia Estructurada de Contexto

Archivos: sections.parquet, chunks.parquet.

Fragmentos y secciones preparadas para RAG. Conservan el contexto discursivo y permiten citar sección y página de manera limpia.

Nivel 3 — Metadatos y Perfil del Documento

Archivos: documents.parquet.

Identificación del documento, tipo de PDF (digital, escaneado, híbrido), calidad promedio e idioma. Nunca confundir document_id con el nombre de archivo.

Nivel 4 — Calidad y Auditoría de Incertidumbre

Archivos: quality_report.json, integrity_report.json.

Alertan sobre páginas dudosas o con bajo OCR que requieren advertencia de incertidumbre antes de ser citadas por el agente.

3.2. Protocolo de Citación Bibliográfica Dual Obligatoria

Todo agente que utilice este corpus debe citar obligatoriamente la ubicación física en el archivo PDF junto con la numeración impresa formal.

[{filename}, Sec. "{section_title}", Pág. PDF {page_start}, Pág. Impresa {page_label_start}]
Ejemplo de Citación Textual Válida:

"El 68% de los docentes consultados afirma utilizar herramientas basadas en LLMs para la planificación didáctica [Informe_IA_Educacion_Ninez_CIOdD_2026.pdf, Sec. '1. Resumen Ejecutivo', Pág. PDF 2, Pág. Impresa ii]."

Ejemplo de Citación Tabular Válida:

"En la región Central Occidental, la adopción docente alcanzó el 74.2% [Tabla 1: 'Distribución porcentual de uso de LLM', Pág. PDF 2, ID: tbl_08f91a2bc41029aa]."

3.3. Cuatro Anti-Patrones Prohibidos para el Modelo de Lenguaje

❌ PROHIBIDO CITAR PÁGINAS POR EL OVERLAP

Las palabras de solapamiento (overlap_words) provienen del chunk anterior. La citación debe reflejar exclusivamente las páginas cubiertas por las palabras propias (unique_words).

❌ PROHIBIDO ASUMIR year_candidates COMO FECHA OFICIAL

Los años inferidos en la portada son candidatos estadísticos de frecuencia (pueden ser metas futuras como "Estrategia 2030"). Citar siempre como "año referenciado en el texto".

❌ PROHIBIDO SUMAR word_count PARA VOLUMEN LÉXICO

Sumar word_count sobrecuenta las palabras por el solapamiento de 80 palabras. Para auditorías de volumen real debe sumarse siempre SUM(unique_words).

❌ PROHIBIDO CONFUNDIR CALIDAD TÉCNICA CON MÉRITO CIENTÍFICO

Un puntaje de average_quality = 0.96 mide fidelidad de la extracción digital, no rigor metodológico de la investigación del autor original.

SANEAMIENTO HEURÍSTICO

Los 6 Ciclos de Depuración y Limpieza del Pipeline

Cómo el pipeline detecta y neutraliza las anomalías estructurales típicas de los documentos PDF para producir un corpus científicamente íntegro.

Ciclo 1: Inferencia de Bordes con Comodín '#' (infer_repeated_lines)

Examina las 3 primeras y 3 últimas líneas de cada página. Normaliza los dígitos a # (ej. "Informe 2026 - Pág. 12" $\to$ "informe #### - pág. ##"). Si el patrón se repite en $\ge 35\%$ de las páginas, se elimina exclusivamente en los bordes, evitando borrar cifras legítimas dentro del cuerpo del texto.

Ciclo 2: Democión de Encabezados Repetidos (demote_repeated_headings)

En documentos de $\ge 8$ páginas, identifica bloques con is_heading = True que se repiten en $\ge 4$ páginas o $\ge 8\%$ del total. Estos bloques son cabeceras corridas o títulos de capítulo repetitivos; se degradan a texto de cuerpo para no fragmentar artificialmente la sección.

Ciclo 3: Clasificador Heurístico de Tablas vs. Prosa (AdaptiveTableExtractor)

Evalúa la proporción de celdas que inician en minúscula (lower_start_ratio). Si $\ge 25\%$ inician en minúscula o la rejilla ocupa $\ge 70\%$ del área de la página, se clasifica como prosa fragmentada en columnas y se aísla en tables_rejected.jsonl con su motivo explícito.

Ciclo 4: Fusión No-Destructiva de Secciones Cortas (ChunkBuilder)

Toda sección con $< 60$ palabras se fusiona dentro del chunk anterior, registrando merged_section_ids y merged_section_titles. Si no existe chunk anterior, se emite con la bandera short_section = True. Se audita que chunk_coverage ≥ 0.995.

Ciclo 5: OCR Adaptativo con Doble Disparador (OCRExtractor)

Solo activa Tesseract OCR (200 DPI, spa+eng) si el texto nativo tiene $< 80$ caracteres, $< 20$ palabras o calidad $< 0.35$. Sustituye al nativo únicamente si aporta $> 20\%$ más palabras legibles.

Ciclo 6: Auditoría de Consistencia de 9 Reglas (check_integrity)

Verifica unicidad de IDs, coherencia de páginas extraídas frente al PDF original, integridad referencial de secciones, ausencia de páginas huérfanas y ausencia de colisiones inter-documento en integrity_report.json.

ARQUITECTURA DE BÓVEDAS

Integración con Bóvedas de Conocimiento: Brain OS v1.6

Cómo el CIOdD-UCR PDF Intelligence Pipeline sirve como el motor de ingesta fundamental para alimentar Bóvedas de Conocimiento y asistentes operativos (Jaime Figueres / FAIR.cr).

En la arquitectura de Brain OS, la inteligencia artificial no opera como un simple chatbot de conversación, sino como un colaborador operativo que gestiona proyectos, recuerda acuerdos y redacta documentos listos. Sin embargo, el conocimiento institucional se encuentra mayoritariamente bloqueado en archivos PDF estáticos.

El PDF Intelligence Pipeline actúa como la Capa 0 (Compilador Documental Primario) que desbloquea este conocimiento y lo traduce a las 4 capas funcionales de Brain OS:

Capa 0: Ingesta Cruda
PDF Intelligence V5.2

Extracción limpia, OCR adaptativo, bboxes y tablas con huella criptográfica SHA-256 inmutable.

Capa 1: Compilador
Markdown & HTML

Compilación de notas atómicas en Obsidian y generación de tableros interactivos para revisión.

Capa 2: Memoria
Daily Logs & Flush

Memoria de corto plazo (bitácoras) sincronizada con la biblioteca de claims de largo plazo.

Capa 3: Agente Autónomo
Colaborador Operativo

Agentes RAG que consultan DuckDB y FAISS para responder con citas verificables de documento y página.

ANALÍTICA RELACIONAL

DuckDB SQL Cookbook — Consultas de Alto Rendimiento

Sentencias SQL canónicas para científicos de datos y agentes RAG sobre el archivo corpus.duckdb.

Consulta 1: Inventario Documental y Cobertura de Chunks

SELECT 
    document_id,
    filename,
    inferred_title,
    page_count,
    total_chunks,
    SUM(unique_words) AS total_palabras_reales,
    ROUND(chunk_coverage * 100, 2) AS porcentaje_cobertura
FROM chunks
JOIN documents USING (document_id)
GROUP BY document_id, filename, inferred_title, page_count, total_chunks, chunk_coverage
ORDER BY total_palabras_reales DESC;

Consulta 2: Cruce de Fragmentos de Alta Calidad con Tablas Asociadas

SELECT 
    c.chunk_id,
    c.filename,
    c.section_title,
    c.page_start,
    c.page_label_start,
    c.quality_score,
    t.table_id,
    t.caption,
    t.markdown
FROM chunks c
LEFT JOIN tables t 
    ON c.document_id = t.document_id 
    AND t.page_number BETWEEN c.page_start AND c.page_end
WHERE c.quality_score >= 0.85
  AND c.text ILIKE '%inteligencia artificial%'
ORDER BY c.quality_score DESC
LIMIT 10;

Consulta 3: Detección de Secciones Cortas Absorbidas

SELECT 
    chunk_id,
    filename,
    section_title AS titulo_principal,
    merged_section_titles,
    unique_words,
    word_count
FROM chunks
WHERE array_length(merged_section_ids) > 0
LIMIT 20;

Manual de Instalación y Uso del Paquete `pdf_intelligence`

Instrucciones completas para instalar el paquete en entornos locales, servidores y Google Colab.

1. Instalación del Paquete en Modo Desarrollo

# Clonar repositorio
git clone https://github.com/tu-usuario/pdf-to-rag-pipeline.git
cd pdf-to-rag-pipeline

# Instalar dependencias del sistema (Tesseract OCR bilingüe)
# En Ubuntu / Debian:
sudo apt-get install -y tesseract-ocr tesseract-ocr-spa tesseract-ocr-eng

# Instalar paquete Python (PEP 621)
pip install -e .

# Con soporte opcional para Embeddings multilingües y FAISS:
pip install -e ".[embeddings]"

2. Comandos de la Interfaz de Línea de Comandos (CLI)

# Procesar directorio completo de PDFs
pdf-intelligence process --input ./data/pdfs --output ./data/pdf_intelligence

# Búsqueda léxica offline rápida con TF-IDF (0 tokens consumidos)
pdf-intelligence search "gobernanza algorítmica" --top-k 5

# Auditar reporte de integridad y páginas marcadas
pdf-intelligence audit --output ./data/pdf_intelligence

3. Uso como Módulo Python en Scripts o Pipelines RAG

from pdf_intelligence import PipelineConfig, CorpusBuilder, LocalSearch

# 1. Configurar hiperparámetros
config = PipelineConfig(
    pdf_directory="./data/pdfs",
    output_directory="./data/pdf_intelligence",
    ocr_enabled=True,
    chunk_target_words=550,
    chunk_overlap_words=80
)

# 2. Ejecutar procesamiento
builder = CorpusBuilder(config)
builder.process()

# 3. Consultar índice local
searcher = LocalSearch("./data/pdf_intelligence")
results = searcher.search_tfidf("desarrollo cognitivo", top_k=3)
for r in results:
    print(f"[{r['chunk_id']}] Pág: {r['page_start']} | {r['section_title']}")
